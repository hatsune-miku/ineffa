# 后端

平台账号和个人空间均可选择 OpenCode 或 Pi。修改账号默认后端会应用于今后新建的会话。平台 `/new` 使用账号当前选择，个人空间重置沿用原后端。

在「会话设置」中切换后端，选择目标模型并确认即可。账号在目标后端已绑定模型时会自动沿用。请先等待生成、排队输入、交互问题和平台投递完成。

切换本身没有模型调用。新后端在第一条普通输入中收到近期发言及已完成工具的文本结果，保留作者和顺序。历史按最近 64 条、约 24,000 字符截取，单条最多约 4,000 字符。原会话归档后仍可回看完整记录。尚未触发回复的群聊消息随新绑定继续等待。

| 能力 | OpenCode | Pi |
| --- | --- | --- |
| 模型 | 原生提供方及自定义服务 | WebUI 配置的 OpenAI 兼容服务，必须指定模型 |
| 流式、工具、取消 | 支持 | 支持 |
| 排队 | queue / steer | queue |
| 平台提问、发送附件 | 支持 | 支持 |
| 工具目录按需加载 | 支持 | 支持 |
| MCP、浏览器 | 支持 | 按需连接全局配置的 stdio、HTTP 服务和内置 Playwright |
| Skills | 本地与 URL 来源 | 全局配置中显式列出的本地路径 |
| 手动压缩 | 支持 | 支持 |
| Agent 切换、会话权限规则 | 支持 | 工具默认允许。具有询问或拒绝规则的会话需先处理规则才能切换 |
| 调试 | HTTP/SSE、工具、Token 与缓存 | 同类统计，HTTP/SSE 来自模型请求的实际响应 |

账号修改绑定模型后，同后端的未归档会话使用新模型；当前生成不打断。Pi 在下一条输入执行时应用模型变化。其他后端的旧会话保留自己的模型，可在会话设置中修改。

Pi 按接收顺序处理输入。当前 SDK 的 steer 队列只保存在内存中，缺少能与平台消息对应的持久输入 ID，因此 WebUI 在 Pi 会话中只提供排队。

Pi 使用 `@earendil-works/pi-coding-agent` 1.6.0，原生会话保存在 `.ineffa/pi/sessions/`。模型、MCP 和 Skills 路径共用 WebUI 管理的全局配置。Pi 在下一次处理输入时读取资源配置，工具仍由 SDK 执行。环境中的 AGENTS.md、其他 Skills 和扩展不会自动加载。

Pi 按需读取 Skill 正文。若只改了文件中的名称或描述，新会话会读取最新目录，已有会话可在重启服务后刷新。MCP 连接失败时，其余工具仍可使用，再次调用目录工具可重试。

Pi 的原生 JSONL 保存执行历史；`delivery.sqlite` 只用于输入接收、平台投递事件和原生消息 ID 对照。服务异常退出后，已接收但未开始的输入继续排队，执行中的输入停止并标明中断，不自动重跑可能已经产生副作用的工具。重新提交前先检查上次结果。

两种后端的导出文件保留各自原生格式，不能互相直接导入。配置导入导出包含账号后端选择和共享模型配置，不包含会话历史。
